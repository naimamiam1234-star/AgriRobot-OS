# الروبوت الزراعي — مواصفات التصميم v1

التاريخ: 2026-10-19

الحالة: تصميم للمراجعة قبل كتابة برامج التشغيل. لا يمثل روبوتًا مركبًا أو مختبرًا، ولا ملف نظام جاهزًا للإقلاع.

## الهدف ونطاق النسخة الأولى

روبوت صغير لممر تجريبي أو مشتل، يراقب محصولًا واحدًا، يقيس رطوبة التربة، يسقي بكمية مقاسة، ويحفظ صورًا ونتائج قبل التدخل وبعده. يحمل خزانين مستقلين للماء والسماد السائل. يعمل دون إنترنت بعد تجهيز البرمجيات والنماذج، ويستفيد من الإنترنت للبحث والتحليل الإضافي والمزامنة.

النجاح يقاس بصحة الكمية المنفذة، وثبات التوقف عند العطل، واكتمال السجلات، ودقة الرصد على صور حقيقية. لا نفترض نسبة توفير للماء قبل تجربة مقارنة.

## قرارات النظام

| الطبقة | الاختيار | المسؤولية |
|---|---|---|
| النظام | Ubuntu Server 24.04 LTS 64-bit | الخدمات والتخزين والشبكة |
| تنسيق الروبوت | ROS 2 Jazzy، الحزم اللازمة فقط | ربط القياس والحركة والرؤية |
| واجهة الاستخدام | واجهة محلية عبر الهاتف | الحالات والموافقات والتقارير |
| التحكم | STM32 متصل عبر USB-UART أو USB أصلي إذا دعمه البرنامج | المحركات والمضخات والمستشعرات |
| المحادثة | Qwen3-0.6B، نسخة GGUF Q4 عبر llama.cpp | إجابات قصيرة من البيانات والمعرفة المحلية |
| التعرف على الكلام | Whisper tiny متعدد اللغات عبر whisper.cpp | صوت إلى نص عند الطلب |
| الرد الصوتي | Piper وصوت عربي بعد اختبار الترخيص والجودة | قراءة الردود والتنبيهات |
| الرؤية الأساسية | YOLO11n، مرشح للتخصيص | تحديد الأجسام المدربة فقط |
| وصف الصورة | SmolVLM2-256M اختياري | وصف صورة عند التوقف، ليس تشخيصًا مؤكدًا |
| الذاكرة | SQLite وصور محفوظة محليًا | النباتات والقياسات والأحداث والمزامنة |

هدف تجهيز مبدئي: حاسوب 64 بت، RAM قدرها 8GB وSSD. هذا هدف هندسي وليس حدًا مثبتًا؛ الأداء يعتمد على المعالج والنماذج والسياق. مع 4GB نبدأ دون وصف صور توليدي، وبالتناوب بين المهام. لا نشغل نماذج الذكاء الاصطناعي على STM32.

## تقسيم المسؤوليات

1. STM32 يضبط سرعة العجلات ويقرأ المستشعرات وينفذ جرعة مصرحًا بها ضمن حدود ثابتة.
2. خدمة القياسات تتحقق من صلاحية القراءة وعمرها ومعايرتها ووحدتها.
3. خدمة الرؤية تحفظ الصورة وتنتج ملاحظة ودرجة ثقة؛ الثقة ليست احتمال صحة مثبتًا قبل المعايرة.
4. خدمة القرار تطبق قواعد المحصول وحدود الماء والسماد وحالة الجهاز.
5. المساعد اللغوي يقرأ نتائج الخدمات ويشرحها؛ لا يمتلك قناة مباشرة للمضخات أو طرفية النظام.
6. خدمة المزامنة ترسل السجلات وتستقبل النتائج الاستشارية. لا تعيد تشغيل تدخل قديم.

## دائرة السوائل

مسار الماء منفصل عن مسار السماد. لا نجمع مخارج المسارين دون تصميم يمنع الرجوع والتلوث. إذا كان السماد مركزًا فلا يطبق مباشرة: يلزم تخفيف بوصفة محددة أو خزان محلول جاهز. لا نستنتج نقص عنصر أو جرعة من لون الورقة وحده.

تسلسل الجرعة: تحقق من هوية النبات → قراءة حديثة صالحة → تحقق من وصفة وحدود الجرعة وآخر تدخل → موافقة مطلوبة في النسخة الأولى → تشغيل → قياس الكمية الفعلية → إغلاق → حفظ النتيجة. عند نقص السائل أو تدفق غير متوقع أو تجاوز زمن الضخ، توقف العملية ولا تستأنف تلقائيًا.

## الاتصال بالحاسوب

رسائل محددة الحقول تتضمن رقمًا تسلسليًا ونوع الرسالة والوحدات ورمز تحقق. الأوامر تشمل التمكين والتوقف وسرعة محدودة وطلب جرعة واحدة ومعرفها. القراءات تشمل الإنكودر والجهد والتيار والمستويات والتدفق والأعطال.

لا ينفذ المتحكم معرف جرعة منجزًا سابقًا. بعد إعادة التشغيل يبقى التنفيذ متوقفًا حتى مراجعة حالة الجرعة المعلقة. مهلة فقد الاتصال تضبط بعد الاختبار؛ القيمة المبدئية للاختبار على منصة ثابتة 500ms، ولا تعد اعتمادًا لسلامة الحركة.

## حالات التشغيل

إقلاع → فحص ذاتي → انتظار → حركة → توقف للفحص → اقتراح تدخل → انتظار موافقة → تنفيذ → تسجيل → متابعة.

يمكن الانتقال من أي حالة إلى توقف طوارئ أو عطل. إلغاء الطوارئ لا يعيد الحركة تلقائيًا. عند فقد موقع النبات أو تعطل الحساس أو انخفاض الطاقة تتوقف المهمة أو تعود وفق شروط مسار مجرّب؛ لا نفترض أن العودة آمنة دائمًا.

## الإنترنت والعمل المحلي

- الوضع المحلي: القياس والحركة والرؤية والمحادثة والسجلات وواجهة الهاتف تعمل دون خدمة خارجية بعد التثبيت.
- الوضع المتصل: تحديث الطقس والبحث وإرسال حالة مختارة للتحليل السحابي، ضمن إعداد مشاركة البيانات.
- بعد انقطاع الاتصال: إلغاء الطلب السحابي بعد مهلة وعرض نتيجة محلية مع بيان محدوديتها.
- المزامنة ترسل الأحداث بمعرفات ثابتة لمنع التكرار. الرد السحابي استشارة يعاد التحقق منها محليًا قبل أي تدخل.
- كل معلومة خارجية لها مصدر وتاريخ؛ التوقع القديم يظهر منتهي الصلاحية حسب مدة يحددها نوع المصدر.
- الوصول البعيد يحتاج مصادقة وتشفيرًا؛ لا نفتح منفذ تحكم عامًا. تحديث النماذج والبرنامج عند التوقف مع إمكانية الرجوع للإصدار السابق.

## جدولة الذكاء الاصطناعي

أثناء الحركة تعطى الأولوية للتحكم وقراءة العوائق. الرؤية تستخدم دقة ومعدل صور يحدده الاختبار. المحادثة قصيرة السياق وتحمّل عند الطلب. وصف الصور يبدأ بصورة واحدة عند التوقف. نقل الصوت بزر ضغط للتحدث في البداية لتقليل أخطاء ضجيج الحقل. عند ضغط الذاكرة تغلق المهام الاختيارية؛ التحكم والتوقف لا يعتمدان على اكتمال جواب لغوي.

نماذج اللغة والرؤية عامة وليست اختصاصيًا زراعيًا معتمدًا. نبدأ برصد حالات محددة مثل وجود بقع أو اختلاف نمو، ونضيف تشخيصات فقط بعد بيانات وتقييم ومراجعة مختص. لا تنفذ أوامر علاج مستخرجة من نص على صورة أو صفحة ويب.

## ذاكرة النباتات

لكل نبتة: معرف، منطقة، محصول ومرحلة نمو، موقع تقريبي، صور مؤرخة، قراءات مع الوحدات والمعايرة، ملاحظات الرؤية، تدخلات مقترحة ومعتمدة ومنفذة، كمية فعلية، نتائج متابعة، وتصحيح الفلاح. السجل يميز بين عدم التحسن وعدم توفر قياس مناسب. حفظ السجل لا يساوي إعادة تدريب النموذج تلقائيًا.

## إضافات ذات أولوية

1. فحص ذاتي عند كل انطلاق.
2. تنبيه نصي ومصور وصوت اختياري.
3. متابعة الانسداد والتسرب وفراغ الخزانات.
4. حد أقصى لكل جرعة ومجموع يومي لكل نبتة.
5. تصوير ثابت المسافة مع مرجع لوني عند الحاجة.
6. تنظيف المسبار لتقليل حمل الملوثات بين المناطق.
7. زيارات متابعة حسب المحصول ونوع التدخل.
8. تسجيل الحالات غير المؤكدة وطلب فحص إضافي.
9. تقرير الماء والطاقة والمساحة التي فحصت فعليًا.
10. استئناف الجولة بعد المراجعة دون تكرار تدخل منجز.
11. حزم معرفة وإعدادات لمحصول واحد ثم توسيعها تدريجيًا.
12. حفظ تصحيحات الفلاح لمراجعتها وتطوير النموذج لاحقًا.

هذه تحسينات تصميم، ولا ندعي جدة عالمية لأي منها.

## ما نحتاجه لإغلاق الاختيارات

مواصفات المعالج والرام والمعمارية، القطع الموجودة، الميزانية، المحصول، عرض الممر والتربة والانحدار، مدة العمل المطلوبة، وسعة السوائل المطلوبة. الافتراض المؤقت: حاسوب x86_64، أرض مستوية، محصول واحد وممر تجريبي وإشراف بشري. لا تمتد نتائج هذا النموذج تلقائيًا لحقل واسع أو تضاريس وعرة.
