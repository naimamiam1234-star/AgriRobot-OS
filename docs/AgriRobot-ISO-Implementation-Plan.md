# AgriRobot ISO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. Execution method: native, in this session; no delegated agents.

**Goal:** بناء توزيعة روبوت زراعي Ubuntu 24.04 amd64 قابلة للإقلاع، وبرنامج محلي يعمل بالإنترنت وبدونه، مع اختبارات ومخرجات موثقة.

**Architecture:** قاعدة Ubuntu صغيرة مع casper وإقلاع BIOS/UEFI، وخدمات systemd منفصلة للبرنامج والاتصال وROS 2. التحكم الحقيقي يبقى معطلًا حتى تعريف العتاد ومعايرة الجرعات؛ المحاكاة موسومة بوضوح. لا تكتب النسخة التجريبية على قرص داخلي تلقائيًا.

**Tech Stack:** Ubuntu 24.04 LTS, ROS 2 Jazzy, Python, SQLite, systemd, GRUB, SquashFS, xorriso, QEMU, llama.cpp.

**Spec:** AgriRobot-Design-v1.md، مع توسعة هذه الخطة الخاصة بصورة الإقلاع.

## Global Constraints

- Ubuntu Server 24.04 LTS 64-bit؛ الهدف الأول حاسوب x86_64؛ ليست صورة STM32 أو ARM.
- العمل المحلي بعد تنزيل البرمجيات والأوزان وتجهيزها مسبقًا.
- منع تحكم النموذج اللغوي المباشر في الحركة والجرعات.
- حالات محاكاة وعتاد حقيقي منفصلة؛ لا توصف بيانات اصطناعية بأنها قياسات.
- مفاتيح الخدمات الخارجية لا تدخل في الصورة؛ الإعداد على الجهاز بعد التشغيل.
- لا ادعاء بوجود نموذج زراعي مدرب أو زمن إقلاع مضمون دون اختبار.
- الاحتفاظ بجميع المعلومات والإضافات في دليل محلي، مع بيان ما هو منفذ وما هو مؤجل.

## Review Focus

1. إعادة التشغيل أثناء جرعة: لا تكرر الجرعة ولا تستأنف تلقائيًا؛ اختبار في المهمة 1.
2. انقطاع الإنترنت والردود القديمة: المحلي يبقى متاحًا والاستشارة القديمة لا تنفذ؛ اختبار في المهمة 2.
3. غياب ملفات النماذج أو الكاميرا: حالة غير متاح واضحة دون نتائج مختلقة؛ اختبار في المهمة 3.
4. Live USB بلا تخزين دائم: تحذير واضح بأن السجلات قد تفقد، ولا يُفعّل التحكم الحقلي دون تخزين دائم؛ اختبار في المهمة 4.
5. جهاز ضعيف أو إقلاع دون شبكة: تظهر الحالة أولًا وتحمل النماذج لاحقًا؛ اختبار في المهمة 6.

## Task 1: Runtime and durable event store

**Files:** app/core.py, app/store.py, app/controller.py, tests/test_controller.py.

**Interfaces:** Controller.request_dose(request_id, plant_id, volume_ml), Controller.stop(), Store.record_event(event). يبدأ Controller في وضع disabled ويقبل مدخلات محددة الوحدات فقط.

- [ ] كتابة اختبارات رفض القيم السالبة وغير المنتهية والمعرف المكرر والجرعة دون اعتماد، ثم تشغيلها والتأكد من فشلها قبل التنفيذ.
- [ ] تنفيذ آلة الحالات وسجل SQLite بمعاملات؛ الجرعة المعلقة بعد الإقلاع تحتاج مراجعة.
- [ ] اختبار توقف الطوارئ وفقد الاتصال وعدم الانطلاق عند إعادة التمكين.
- [ ] تشغيل اختبارات الوحدة وحفظ النتائج؛ commit عند توفر مستودع محلي.

## Task 2: Local service and connectivity

**Files:** app/server.py, app/connectivity.py, app/sync.py, tests/test_service.py.

**Interfaces:** GET /health, GET /status, GET /events; الأوامر POST مع مصادقة محلية وحماية من طلبات المتصفح غير المصرح بها، Controller من المهمة 1.

- [ ] اختبارات طلبات غير مصادق عليها وانقطاع الشبكة وتكرار المزامنة ورد قديم.
- [ ] تنفيذ الخدمة المحلية، مهلات الاتصال وطابور أحداث بمعرفات ثابتة؛ لا تعاد أوامر الحركة والضخ من طابور الشبكة.
- [ ] اختبار سلامة الخدمة دون شبكة والتحقق من حدود حجم المدخلات.
- [ ] توثيق الوصول من هاتف على الشبكة المحلية؛ لا فتح تلقائي لمنفذ على الإنترنت.

## Task 3: AI and camera adapters

**Files:** app/ai.py, app/vision.py, app/audio.py, config/models.json, scripts/fetch-models.py, tests/test_adapters.py.

**Interfaces:** chat(messages), inspect_image(path), transcribe(path), speak(text) ترجع بيانات مع حالة unavailable/error عند غياب المصدر؛ لا تمرر أوامر إلى Controller.

- [ ] اختبارات أوزان مفقودة ومهلات واستجابة خادم غير صالحة وكاميرا غائبة وضغط الذاكرة.
- [ ] دمج Qwen3-0.6B GGUF وwhisper.cpp وPiper، وYOLO11n ككاشف عام موسوم؛ وصف SmolVLM2-256M اختياري.
- [ ] تنزيل الأوزان من مصادر مثبتة في manifest مع الحجم وSHA256 والترخيص؛ تفشل حزمة offline الكاملة إذا نقص وزن مطلوب.
- [ ] اختبار استدلال حقيقي حين تتوفر الأوزان وتسجيل زمنه؛ البدائل الوهمية للاختبارات فقط.
- [ ] تضمين توثيق واضح للحاجة لتدريب وتقييم نموذج المحصول؛ لا توزيع نموذج عام بوصفه مشخص أمراض.

## Task 4: Operator interface and local handbook

**Files:** app/ui/, docs/operator-ar.md, docs/hardware-ar.md, docs/features-status.md, tests/test_ui_contract.py.

**Interfaces:** واجهة عربية RTL تستهلك status/events وتعرض حالة كل حساس وخزان ونموذج، مع زر طوارئ برمجي لا يحل محل الزر المادي.

- [ ] إعداد التصميم المرئي باستخدام مهارة UI المطلوبة قبل تنفيذ الواجهة.
- [ ] عرض المحاكاة وحالة عدم اتصال STM32 وعدم دوام التخزين بوضوح، دون قراءات افتراضية مضللة.
- [ ] نقل إضافات التصميم الـ12 وسيناريوهات النبات والخزانين إلى دليل محلي مع حالة التنفيذ لكل بند.
- [ ] فحص الواجهة على الهاتف والحاسوب ولوحة المفاتيح ومراجعة لقطات التشغيل.

## Task 5: Reproducible image builder

**Files:** iso/build.sh, iso/packages.list, iso/overlay/, iso/grub.cfg, scripts/preflight.sh, scripts/check-artifact.sh, build/manifest.json.

**Interfaces:** preflight.sh يطبع المتطلبات الناقصة ويخرج برمز غير صفري؛ build.sh ينتج dist/AgriRobot-0.1-amd64.iso وSHA256SUMS وسجل الحزم والأوزان عند نجاح كل الخطوات فقط.

- [ ] اختبار preflight في البيئة الحالية: لا CAP_SYS_ADMIN ولا CAP_SYS_CHROOT، ولا أدوات ISO/QEMU مثبتة. لا صلاحية mount أو chroot مفترضة لمجرد uid=0.
- [ ] تجهيز مسار بناء على Ubuntu حقيقي بصلاحيات مناسبة، تنزيل حزم موقعة والتحقق من المصدر، وإنشاء rootfs وkernel وinitrd وSquashFS.
- [ ] إضافة GRUB لBIOS وUEFI وخدمات systemd ومستخدم تشغيل محدود الصلاحيات وأذونات أجهزة محددة.
- [ ] لا installer ماسح أقراص؛ النسخة الأولى Live USB. دليل مستقل لتجهيز تخزين دائم مع تحديد القرص صراحة وعدم التنفيذ الآلي.
- [ ] ضغط مناسب لسرعة القراءة والإقلاع، تحميل النماذج عند الطلب، وعدم انتظار الشبكة لظهور حالة البرنامج. لا إزالة تعريفات لازمة قبل اختبار العتاد.
- [ ] التحقق من محتويات ISO وكتالوج الإقلاع وchecksums؛ لا يعتبر نجاح إنشاء أرشيف دليلًا على الإقلاع.

## Task 6: Boot verification and release

**Files:** tests/boot/, docs/validation.md, dist/release-notes.md.

- [ ] تشغيل الصورة بمحاكاة QEMU BIOS وUEFI، أولًا دون شبكة ثم مع شبكة.
- [ ] تسجيل الوصول للخدمة، حالات غياب العتاد والنماذج والتخزين، وفشل تشغيل خدمة فرعية.
- [ ] قياس زمن الإقلاع وزمن جاهزية البرنامج وذروة الذاكرة وزمن كل نموذج مع تسجيل CPU/RAM ونوع وسيط التخزين.
- [ ] اختبار نسخ السجلات واستعادتها وعدم تكرار جرعة بعد إعادة التشغيل بالمحاكاة؛ العتاد يحتاج اختبار منصة منفصلًا.
- [ ] نشر تقرير يميز checked / failed / not run مع سبب كل اختبار غير منفذ. تسليم ISO فقط إذا تم إنتاجه فعليًا، وإلا تسليم المصدر مع العائق المحدد.

## Environment findings — 2026-10-19

المضيف Ubuntu 24.04.3 ومساحة متاحة نحو 30GB. المستخدم root لكن CapEff وCapBnd كلاهما صفر. xorriso وdebootstrap وmksquashfs وgrub-mkrescue وqemu-system-x86_64 غير موجودة، ولم يظهر /dev/kvm أو loop-control. هذه قيود مسار البناء المعتاد؛ لا تثبت استحالة جميع طرق البناء دون صلاحيات. لم ننزل نظامًا أساسيًا أو ننتج ملف ISO بعد.
