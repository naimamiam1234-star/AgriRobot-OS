# سجل المتحكمات — تنفيذ المضيف الأول

نُفذ سجل للقراءة فقط في app/device_registry.py وواجهة GET /robot/context المصادق عليها. لا يوجد بعد ناقل UART/USB حي أو firmware للوحات؛ لا تمثل ملفات replay أجهزة فعلية. الافتراضي قائمة لوحات فارغة، ويظل physical_output=false دائمًا.

ملف config/assemblies/example-readonly.json مثال تعليمي لا يحدد أرجلًا فعلية ولا يثبت وجود حساس. اسم ANALOG_SOIL منفذ منطقي يجب استبداله بتوصيل موثق عند تنفيذ الناقل والـfirmware. يمنع المدقق تكرار board_id/component_id واستعمال المنفذ المنطقي نفسه لقطعتين. عند استخدام ناقل مشترك يجب أن يميز الملف نقطة النهاية/العنوان؛ لا يساوي الاشتراك في الناقل نفسه تعارض أرجل.

## البروتوكول المنفذ

سطر UTF-8 JSON أقصاه 768 بايت بما فيه newline. الغلاف يحتوي حقلين فقط: body نص JSON خام، وcrc32 ثمانية أرقام hexadecimal صغيرة. CRC32 يحسب على بايتات UTF-8 للنص body قبل تهريبه داخل الغلاف. لا يلزم ترتيب مفاتيح canonical عند الإرسال، لأن البصمة على النص المنقول نفسه. البصمة لكشف تلف النقل وليست مصادقة للهوية.

نص body يحتوي بالضبط v=1 وboard_id وsession وseq وtype وpayload. seq عدد صحيح غير سالب حتى 2^32-1؛ لا يقبل bool. معرفات ASCII محدودة إلى 64 حرفًا. الأنواع المنفذة:

- hello: أول إطار seq=0، وpayload يحتوي firmware فقط؛ يقارن بإصدار التجميعة المتوقع. التطابق لا يثبت الهوية تشفيريًا.
- heartbeat: payload فارغ. يحدث صلاحية الاتصال ولا يجدد عمر القياسات السابقة.
- telemetry: payload يحتوي component_id وvalue وunit فقط؛ القطعة والوحدة يجب أن تتطابقا مع التجميعة. القيمة عدد منتهٍ بين -10^12 و10^12؛ هذا حد مدخل عام وليس نطاق معايرة حساس.

المضيف ينشئ session جديدة لكل اتصال عبر open_session؛ يجب أن يرسلها ناقل موثوق مستقبلًا كتحدٍّ للوحة قبل hello. إعادة استخدام session مرفوضة خلال عمر السجل. الميزانية 64 جلسة لكل لوحة ثم يرفض الاتصالات حتى إعادة تهيئة السجل؛ لا يجوز استخدام هذا الحد كآلية تحكم بالحركة. السجل داخل الذاكرة ولا يحتفظ بمقاومة إعادة التشغيل/إعادة إرسال الجلسات عبر إعادة تشغيل المضيف؛ ناقل المستقبل يحتاج سياسة مصادقة وتوثيق جلسات مناسبة.

مهلة الأدلة الافتراضية ثلاث ثوانٍ تشخيصية فقط؛ ليست deadman للمحركات. تقادم الاتصال أو القياس يجعل value الحالية null ويحتفظ بآخر ملاحظة وعمرها موسومة stale. بيانات اللوحة تبقى observed وغير موثقة إلكترونيًا؛ لا يرفع ادعاء اللوحة الحالة إلى identified/verified. تغيير الجلسة يمسح الملاحظات السابقة. إصدار firmware مختلف يعطي conflict ويمنع telemetry. إعادة ترتيب الإطارات وتكرارها والحقول المكررة وNaN والأطر الطويلة ترفض.

manifest_part وcomponent_status وfault وطلبات probes والحركة ليست منفذة في هذا الجزء؛ يرفضها codec بدل تفسيرها بوصفها قياسات.

## التجربة

```sh
python3 -m app.server --data runtime --assembly config/assemblies/example-readonly.json
```

اقرأ /robot/context مع Authorization: Bearer ومفتاح runtime/operator.token. لا توجد واجهة HTTP لإرسال إطارات أو فتح جلسات أو تفعيل عتاد. يمكن للناقل المستقبلي استخدام server.registry داخل العملية بعد توثيق مصدره. لا تتصل طبقة السجل بالمتحكم التنفيذي.

لإعادة تشغيل ملف إطارات مسجل:

```sh
python3 -m app.device_tool --assembly config/assemblies/example-readonly.json --board sensor-board --session example-session frames.jsonl
```

أقصى replay هو 10,000 إطار، ويخرج بخطأ عند أول إطار مرفوض. الناتج موسوم file_replay_no_live_transport. وظائف encode_frame/decode_frame متاحة لإنشاء fixtures واختبار ناقل المستقبل. تبقى معلومات التجميعة تصريحات متوقعة وليست نتائج فحص دارة.

## التحقق والحدود

51 اختبارًا اجتازت محليًا، منها 11 للسجل/الإطارات واختبار HTTP جديد. يتطلب الإكمال firmware مبنيًا لكل لوحة، ناقلًا حيًا محدود الصلاحيات، فحوص تعريف موثقة، سياقًا للمساعد، ثم منصة فعلية ومعايرة مستقلة. الصورة السابقة لا تتغير بإضافة هذه الملفات؛ البناء التالي يضم هذا التنفيذ والمهارات.
